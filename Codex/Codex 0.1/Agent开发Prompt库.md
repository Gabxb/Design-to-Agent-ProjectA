# Agent 开发学习与工作 Prompt 库

> 使用方法：把 `{占位符}` 替换为真实内容。Prompt 不是质量保证，输出必须由测试、评测和人工审查验证。不要粘贴密钥或敏感数据。

## 1. 学习规划教练
```text
你是资深 Agent 工程导师。我的基础：{基础}；每周时间：{小时}；目标岗位：{岗位}；截止日期：{日期}。
请先判断缺口，再给出未来 7 天计划。每项必须包含：产出、预计时长、验收标准、常见失败、复盘问题。
不要只列知识点。优先安排可运行代码、测试和评测。若输入信息不足，最多提出 3 个关键问题。
```

## 2. 官方文档精读
```text
基于我提供的官方文档内容，输出：
1) 关键概念及相互关系；2) 最小可运行示例；3) 生产环境注意事项；
4) 容易误解之处；5) 5 道自测题；6) 一个 60 分钟练习。
只根据提供内容陈述事实，推测必须标注“建议”。
文档内容：{粘贴内容}
```

## 3. 需求转 Agent 设计
```text
把以下业务需求拆成：确定性代码、模型判断、工具、状态、人工审批、评测与非目标。
判断是否真的需要 Agent。如果固定工作流更合适，请明确说明。
对每个工具给出名称、目的、输入 schema、输出 schema、权限、超时、副作用、幂等策略和错误类型。
需求：{需求}
```

## 4. 工具 schema 审查
```text
审查以下 Agent 工具定义。重点检查：职责是否单一、名称是否区分、参数是否强类型、权限是否过大、返回是否稳定、是否可幂等、错误是否可恢复。
输出严重/高/中/低风险问题，并给出修改后的 Pydantic schema。不要改变业务语义。
工具定义：{代码}
```

## 5. Agent 循环代码审查
```text
你是生产级 Python Agent 代码审查者。检查：终止条件、重复调用、超时、重试、并发、预算、状态一致性、工具鉴权、注入风险、日志脱敏、可测试性。
每个问题必须包含：证据位置、触发场景、影响、最小修复、测试用例。
代码：{代码}
```

## 6. RAG 实验设计
```text
为以下 RAG 场景设计一个可复现实验。给出数据集、基线、变量、指标、标注规范、错误分类和停止条件。
必须把检索质量与生成质量分开评估；包含无答案、权限、多跳、表格和提示注入用例。
场景：{场景}
当前方案：{方案}
```

## 7. 生成评测样例
```text
根据我提供的文档生成候选评测题。每题输出 JSON：case_id、question、gold_evidence、must_include、must_not_include、answerable、tags。
题目覆盖事实、多跳、时间限定、否定、无答案和权限边界。
只生成候选集，提醒我必须人工核验；不要虚构文档之外的证据。
文档：{内容}
```

## 8. Trace 排障
```text
根据以下 trace 做根因分析。先建立时间线，再判断失败属于模型、提示、工具、检索、权限、状态、基础设施还是评测。
列出证据、最可能根因、备选假设、最小复现实验、短期修复和长期预防。缺少证据时不要猜。
Trace：{trace}
```

## 9. 提示注入红队
```text
为一个“{场景}”Agent 设计安全测试，不提供真实攻击目标或凭据。
覆盖：间接提示注入、工具越权、数据外泄、跨租户访问、隐藏指令、恶意文件、重复副作用、审批绕过。
每条包含输入、预期安全行为、检测信号和修复建议。
```

## 10. 项目 README 生成
```text
基于以下真实项目信息撰写技术 README。不得编造指标、功能或部署状态。
结构：业务问题、非目标、架构、时序、工具契约、权限、启动、测试、评测、可观测、成本、已知限制、ADR。
缺失信息用 TODO 标注。
项目信息：{信息}
```

## 11. 面试官模拟
```text
你是 Agent 开发岗位面试官。围绕我的项目进行 5 轮深挖，每次只问一个问题，并根据回答追问。
重点：为什么用 Agent、状态与工具、RAG 评测、安全、幂等、故障、成本和取舍。
最后按“技术深度、证据、表达、诚实度”评分，并给出改进计划。
项目：{项目描述}
```

## 12. 简历 bullet 改写
```text
把以下项目经历改成 3 条简历 bullet。只使用我提供的事实和可验证数字，不得补造指标。
每条使用“行动 + 规模 + 方法 + 结果/验证”，突出 Agent 工程、评测、可靠性和安全。
若缺少结果，写成可验证的工程产出而非夸张效果。
经历：{经历}
```

## 13. 每日复盘
```text
根据我的学习日志，帮我输出：今日可验证产出、证据、最大阻塞、根因假设、明日最小任务、需要进入错题库的概念。
如果只有“看了/学了”，把它转成一个可验收任务。
日志：{日志}
```

## 14. 架构决策记录 ADR
```text
把以下技术选择写成 ADR：背景、决策驱动因素、候选方案、决策、理由、后果、风险、回滚、验证指标。
明确区分事实和建议，不把流行度当作理由。
选择：{选型问题}
```

## 15. 发布前检查
```text
充当发布审查人。根据以下变更与证据，检查功能、回归、评测、安全、权限、迁移、可观测、成本、回滚和文档。
输出 Go/No-Go/Conditional Go，列出阻断项及证据。缺少证据默认未验证。
变更：{变更}
证据：{测试与指标}
```
