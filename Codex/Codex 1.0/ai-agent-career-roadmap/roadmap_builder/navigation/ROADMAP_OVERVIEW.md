# AI Agent 学习系统总纲

> 一句话方向：**用工程能力把模型、知识、工具和人工判断连接起来，最终交付可运行、可评测、可部署的 Agent 产品。**

## 1. 先看终点

你不是在学习一堆零散技术，而是在完成一条完整的交付链：

**需求理解 → 数据与 API → LLM 应用 → RAG 知识库 → Agent 工作流 → 测试评测 → 安全部署 → 作品集与求职**

最终应能拿出：

- 3-4 个可运行的作品集项目。
- 至少 1 个非设计领域综合项目。
- 每个项目的 README、架构、测试、安全、评测、部署与 Demo。
- 一份能解释技术取舍的简历和面试答案库。

## 2. 六个阶段总览

| 阶段 | 周期 | 你要解决的问题 | 关键技术 | 阶段成果 |
|---|---:|---|---|---|
| 1. 基础工程 | 1-4 周 | 如何把想法写成可运行服务？ | Python、Git、HTTP、FastAPI、PostgreSQL | 设计需求结构化助手 API |
| 2. LLM 应用 | 5-8 周 | 如何让模型稳定完成任务？ | Prompt、Structured Output、Tool Calling、可靠性 | UX Research Copilot |
| 3. RAG 知识库 | 9-12 周 | 如何让答案基于可引用知识？ | Chunking、Embedding、检索、Reranking、评测 | 设计规范知识库 Agent |
| 4. Agent 工作流 | 13-16 周 | 如何让系统完成多步骤工作？ | State、Workflow、LangGraph、MCP、人工确认 | 智能设计评审 Agent |
| 5. 生产化 | 17-20 周 | 如何让系统可靠、安全、可部署？ | 测试、Tracing、成本、安全、Docker、CI/CD | 可部署的 Agent Web 产品 |
| 6. 求职冲刺 | 21-24 周 | 如何让别人快速相信你的能力？ | README、架构表达、Demo、面试、投递 | 完整求职材料包 |

## 3. 每个阶段的学习闭环

每周都按同一条路径推进：

1. **理解：** 用设计师熟悉的用户、流程、约束和证据来理解概念。
2. **最小实现：** 写一个只有核心输入和输出的小例子。
3. **接入项目：** 把例子接到当前阶段项目。
4. **工程化：** 加入错误处理、日志、测试、权限或成本控制。
5. **表达：** 更新 README、复盘和面试答案。

## 4. 四个项目如何贯穿课程

| 项目 | 重点能力 | 主要阶段 | 求职价值 |
|---|---|---|---|
| 设计需求分析助手 | API、数据库、Structured Output、Tool Calling | W01-W08 | 证明基础工程和 LLM 接入能力 |
| 设计规范知识库 Agent | 文档处理、RAG、引用、权限、评测 | W09-W12 | 证明企业知识场景能力 |
| 智能设计评审 Agent | 状态图、工具、人工确认、Tracing | W13-W20 | 体现设计背景的差异化优势 |
| 供应商风险审查 Agent | 业务状态机、合规、安全、部署 | 综合 | 证明能力可迁移到非设计领域 |

## 5. 现在应该如何选择路径

- 默认执行：**方案 C：设计师优势版**，每周 15-20 小时。
- 时间不稳定：切换到方案 A，保留完整基础和复习缓冲。
- 有明确求职期限且能投入 20-25 小时：切换到方案 B。
- 方案切换不会删除完成记录，只重排未完成任务。

## 7. 一眼判断是否走偏

- 只看资料、不写代码：偏离。
- 只做 Prompt、不做 API、数据库和测试：偏离。
- 只做漂亮 Demo、不做失败路径、安全和评测：偏离。
- 只学设计领域聊天机器人、不做非设计项目：偏离。
- 只打磨项目、不准备 README、Demo 和面试表达：偏离。
