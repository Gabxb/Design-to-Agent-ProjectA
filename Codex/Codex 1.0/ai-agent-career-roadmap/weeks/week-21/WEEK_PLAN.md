# Week 21：作品集工程化整理

## 1. 本周目标

- 建立对“README、架构图、决策记录、截图、演示数据与仓库卫生”的工作级理解。
- 完成：三至四个可审阅的项目仓库。
- 能结合项目解释本周至少两个技术取舍。

## 2. 对应岗位能力

招聘方首先通过仓库结构判断工程成熟度。

## 4. 时间分配

- 概念与示例：20%
- 编码与项目：55%
- 测试、文档与排查：15%
- 复习与自由补充：10%

## 5. 必须掌握

- README
- 架构说明
- 运行指南
- 演示路径

## 6. 需要理解

- ADR
- 版本发布

## 7. 暂时了解

- 开源协作规范

## 8. 本周编码任务

- 在 `weeks/week-21/exercises/` 完成最小练习。
- 在对应项目目录中完成一个可运行里程碑。
- 为关键成功路径和一个错误路径增加测试或验证脚本。

## 9. 本周项目里程碑

求职冲刺：三至四个可审阅的项目仓库。

## 10. 工程要求

- Python 代码使用类型提示；配置不写死本地路径。
- API Key 只从环境变量读取；日志不记录完整密钥或敏感资料。
- 写清运行命令、输入输出、失败表现和验收方法。

## 11. 验收标准

- [ ] 交付物可以按 README 运行。
- [ ] 正常输入和至少一个错误输入被验证。
- [ ] 本周代码、测试、文档和进度记录均已更新。
- [ ] 能口头回答本周面试问题并引用项目例子。

## 12. 常见风险

只展示最终界面，没有问题、约束和取舍。

## 13. 补做任务

- 如果本周未完成，先保留核心闭环：输入 -> 处理 -> 输出 -> 错误处理 -> 运行说明。
- 将非核心优化移到 Day 7 或下一周 `REVIEW.md` 的待办区。

## 14. 提前完成后的进阶任务

- 增加一个失败场景、性能指标或安全约束。
- 对比教学版与生产版差异，并写出一条架构决策记录。

## 15. 本周面试问题

1. 优秀项目 README 应回答什么？
2. 如何解释技术债？

## 16. 周末复盘方式

展示交付物 5 分钟；说明目标、实现、失败、修复和下一步；再填写 `REVIEW.md`。

## 17. 下周准备事项

确认当前代码已提交、环境可重建、未完成任务已记录，并预览下一周的产出定义。
