# Git 与协作

## 1. 这是什么

记录代码变化、支持分支协作和可追溯发布的版本控制系统。

## 2. 为什么 Agent 开发需要它

它参与 Agent 的输入、状态、工具、数据、评测或部署链路，是把模型能力变成可维护产品的基础。

## 3. 设计师可以如何理解

像可合并的设计版本历史，但每次变更都有精确差异和上下文。

## 4. 最小代码示例

```python
git switch -c feat/requirement-api
git add .
git commit -m 'feat: add requirement endpoint'
```

## 5. 工作中的使用方式

代码评审、发布、回滚和多人协作。

## 6. 教学简化方案

先用一个输入、一个处理步骤、一个输出和一个错误案例跑通，不追求通用抽象。

## 7. 生产环境方案

小提交、清晰消息、受保护主分支和自动化检查。

## 8. 常见错误

- 只验证顺利案例。
- 把配置、密钥或本地路径写死。
- 没有记录版本、输入、输出与失败原因。

## 9. 排查方法

缩小为最小复现；核对输入类型和环境；读取最底层错误；检查日志中的请求 ID；再核对最新官方文档。

## 10. 面试问题

1. 这个技术解决什么问题，什么时候不该用？
2. 教学版到生产版需要增加哪些能力？
3. 请结合你的项目说明一次失败和改进。

## 11. 与其他技术的关系

GitHub、CI/CD、代码评审

## 12. 官方文档名称或检索关键词

`Pro Git, branching, pull requests, conventional commits`

框架与 API 可能变化，实施时以最新官方文档为准，不依赖二手教程中的旧接口。
