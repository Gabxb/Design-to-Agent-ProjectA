# AI Agent 开发学习大纲

> **路线主线：**把“理解用户与设计体验”的既有能力，转化为“定义问题、设计人机协同流程、实现可靠服务、评测与交付产品”的 AI Agent 工程能力。

## 0. 先建立正确的全局心智模型

AI Agent 开发不是单纯地调用大语言模型（LLM，Large Language Model，大语言模型）。它是一套由**用户问题、数据与知识、确定性代码、模型推理、工具权限、状态管理、人工确认、评测、安全和部署**共同组成的产品工程系统。

```text
用户价值
  └─ 业务流程与体验设计
       └─ 工程服务与数据
            └─ 模型、检索和工具
                 └─ 评测、安全、观测与部署
                      └─ 可展示的作品集与求职表达
```

## 1. 第一阶段：编程与本地开发基础（Week 01–04）

### 目标

建立可重复运行、可测试、可维护的 Python 后端开发习惯。此阶段的重点不是“快速接模型”，而是先拥有承接模型能力的工程底座。

### 能力树

- Python 3.12：函数、类型提示、数据结构、类、模块、包、异常和日志。
- 开发环境：虚拟环境、依赖、环境变量、命令行、VS Code。
- 协作与接口：Git、GitHub、HTTP、JSON、REST API、OpenAPI。
- 服务与数据：FastAPI、输入验证、SQL、PostgreSQL、仓储边界。
- 质量：单元测试、集成测试、错误响应、README 和可复现命令。

### 阶段项目与证明

**设计需求结构化助手 API**。它证明你能把模糊的设计需求变成具有输入验证、数据模型、API 契约、错误处理、日志和测试的后端服务。

### 阶段检查问题

- 我能否从零创建虚拟环境并解释依赖隔离？
- 我能否设计一个清楚的请求/响应对象和错误响应？
- 我能否用测试证明正常路径和错误路径都能工作？

## 2. 第二阶段：LLM 应用开发（Week 05–08）

### 目标

让模型调用从“能回答”变为“有任务边界、输出可验证、工具执行受控”。

### 能力树

- LLM 基础：Token、上下文、采样、成本与局限。
- Prompt Engineering：角色、目标、上下文、约束、示例和输出格式。
- Structured Output：JSON Schema、字段校验、失败重试与降级。
- Tool Calling：工具定义、参数验证、超时、重试、日志和权限边界。
- 基础安全：提示词注入、外部内容不可信、密钥保护、拒绝高风险请求。

### 阶段项目与证明

**UX Research Copilot**。它将访谈或研究材料转成结构化洞察，并展示你如何让模型输出可解析、可审阅、可追溯。

### 阶段检查问题

- 我能否解释模型建议与应用最终决策的边界？
- 我能否用 Schema 约束工具参数和模型输出？
- 模型失败、超时或返回不完整 JSON 时，系统如何退化？

## 3. 第三阶段：RAG 知识库（Week 09–12）

### 目标

构建一个有证据、有引用、可评测且具备数据隔离意识的检索增强生成（RAG，Retrieval-Augmented Generation）系统。

### 能力树

- 文档流水线：上传、解析、清洗、Chunking（切分）和 Metadata（元数据）。
- 检索：Embedding（嵌入）、向量检索、关键词检索、Hybrid Search（混合检索）。
- 质量：Reranking（重排）、查询改写、引用展示、无法回答时的诚实拒答。
- 安全：权限过滤、数据隔离、来源追溯、过期文档管理。
- 评测：Golden Dataset（金标准数据集）、引用正确率、检索失败分类。

### 阶段项目与证明

**设计规范知识库 Agent**。它证明你能把分散规范转化为有引用依据的知识服务，而不是普通聊天机器人。

### 阶段检查问题

- 我能否解释为什么“检索到相似文本”不等于“回答有依据”？
- 我能否展示引用如何对应原文和访问权限？
- 我如何通过样例集定位是切分、检索、重排还是生成造成的问题？

## 4. 第四阶段：Agent 工作流（Week 13–16）

### 目标

把多步骤 AI 任务实现为可审计、可中断、可恢复和可人工确认的工作流，而不是不可控的自动循环。

### 能力树

- 设计选择：区分确定性 Workflow（工作流）与开放式 Agent（智能体）。
- 状态图：状态、节点、边、条件分支、循环、终止条件和检查点。
- 工具：工具白名单、参数验证、失败重试、超时与结果记录。
- Human-in-the-loop：高风险操作的人类批准、拒绝、修改和恢复。
- LangGraph 与 MCP：状态编排、持久化，以及 Model Context Protocol（模型上下文协议）的工具连接边界。
- 可观测性：Tracing（追踪）、成本统计、请求关联与失败分析。

### 阶段项目与证明

**智能设计评审 Agent**。它证明你能把设计评审从单次模型回答升级为含规则检查、工具调用、人工批准、状态恢复和审计轨迹的服务流程。

### 阶段检查问题

- 什么任务必须采用确定性流程，而不能完全交给 Agent？
- 如何确保高风险操作在批准前绝不执行？
- 如何处理循环、重复工具调用、工具失败和中断恢复？

## 5. 第五阶段：生产化（Week 17–20）

### 目标

让 Agent 系统具备可验证的质量、基本安全和可部署性。

### 能力树

- 测试：单元、集成、端到端、失败回归和测试数据隔离。
- Evaluation（评测）：Golden Dataset、质量量表、自动指标与人工抽检。
- Observability（可观测性）：结构化日志、Tracing、成本、延迟与错误类别。
- 性能与韧性：缓存、限流、超时、重试、熔断和降级。
- 安全：认证授权、最小权限、提示词注入防护、脱敏、审计。
- 交付：Docker、Docker Compose、CI/CD、健康检查、部署、回滚和运行手册。

### 阶段项目与证明

**案例分流与合规助手**。这是非设计领域综合项目，证明你能把 RAG、Tool Calling、Agent 工作流、人工确认、安全、评测和部署组合到一个真实业务流程中。

### 阶段检查问题

- 如何证明系统的“好”不是偶然演示成功？
- 如何保护密钥、用户数据和高风险工具？
- 如果上线后模型质量下降、依赖故障或成本异常，我能看到什么并如何回滚？

## 6. 第六阶段：求职冲刺扩展（Week 21–24）

### 目标

将学习成果改造成招聘方能快速验证的工程作品集与面试证据。

### 能力树

- 项目表达：问题、用户、范围、架构、取舍、失败案例、结果与下一步。
- GitHub：可运行 README、架构图、提交历史、测试、Demo 与安全边界。
- 简历：使用“问题—行动—技术取舍—可验证结果”描述项目，不虚构指标。
- Demo：在 5 分钟内演示正常路径、失败路径、人工确认和工程证据。
- 面试：Python、API、数据库、LLM、RAG、Agent、系统设计、行为问题。
- 模拟任务：需求澄清、任务拆分、交付、复盘和跨职能沟通。

### 最终交付包

## 7. 贯穿全周期的四条质量线

### 7.1 工程质量线

每周都至少留下可运行命令、类型提示、错误处理、测试和 README 更新。不要让“代码能跑”成为唯一标准。

### 7.2 产品与体验质量线

每个项目都先明确用户、任务、成功标准、非目标和人工确认点。设计背景在这里是你的优势，但应通过工程证据兑现。

### 7.3 安全与责任线

密钥只经由环境变量提供；外部内容一律不可信；模型不得绕过应用层直接执行高风险工具；高影响动作必须可追溯、可拒绝、可人工确认。

### 7.4 学习反馈线

每天记录实际结果和问题；每周复盘失败样例；每阶段重看能力矩阵和作品集证据。学习计划可以调整，但已完成成果和个人笔记必须保留。
