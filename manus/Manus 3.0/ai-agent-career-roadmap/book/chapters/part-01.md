# 第 1 部：从设计问题到可运行服务

## 本部承诺

建立 Python、API、数据库、测试与本地开发的工程地基。

## 为什么这一部现在出现

先把设计需求转化为明确的数据模型、接口契约和验收标准，再接入任何模型能力。

## 本部章节

| 章节 | 本周主题 | 本周可验证产出 |
|---|---|---|
| [第 01 章](chapter-01.md) | Python 环境、命令行与可维护脚本 | 可重复运行的 Python 命令行小工具 |
| [第 02 章](chapter-02.md) | Python 数据建模、异常与测试 | 含单元测试的数据转换模块 |
| [第 03 章](chapter-03.md) | Git、HTTP、JSON 与 FastAPI | 带输入验证的 REST API |
| [第 04 章](chapter-04.md) | SQL、PostgreSQL、日志与集成 | 设计需求结构化助手 API 阶段版 |

## 本部项目

本部的主要成果将沉淀到 **[设计需求结构化助手 API](../../projects/project-01-tool-calling/README.md)**。不要等到本部最后一周才打开项目目录；从第一章起就把每周产出连接到项目任务板、README 和测试中。

## 建议阅读与实践节奏

1. 先通读本部四章标题，理解能力的递进关系。
2. 每周先读章节，再读 `weeks/week-XX/WEEK_PLAN.md`。
3. 每天完成 `days/day-XX.md` 的最小闭环，并在 `progress/DAILY_LOG.md` 中写下事实。
4. Day 7 回到本部，检查你是否正向项目里程碑推进。
