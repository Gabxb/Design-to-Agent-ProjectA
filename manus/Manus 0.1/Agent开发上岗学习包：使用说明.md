# Agent开发上岗学习包：使用说明

本学习包面向已有基础 Python、数据结构、数据库和计算机网络知识的计算机科学与技术专业学习者。它的目标是帮助你在 16 周、每周约 20 小时的节奏下，构建两个可展示、可测试、可部署、可解释的 Agent 项目，并形成面试所需的代码、评测、文档和答辩证据。

> **能力边界：**“达到上岗能力”指具备完成受限实际 Agent 项目的工程能力，不代表任何就业、录用、薪资或职位结果的承诺。

## 文件用途

| 文件 | 用途 |
|---|---|
| `Agent开发上岗实战教程.md` | 主教程。包含岗位定位、工程基础、Agent/RAG/安全/评测、两个作品集规格、16 周可验收任务、完整示例代码、面试与结业标准。 |
| `Agent开发上岗实战教程_打印版.pdf` | 适合 A4 阅读与打印的主教程版本。它由 Markdown 生成后应进行字体、分页、代码块与表格的检查。 |
| `Agent开发上岗实战教程_含Prompt.md` | 主教程加上完整 Prompt 库，适合离线检索或复制使用。 |
| `Agent开发Prompt库.md` | 独立的 20 类工程 Prompt。每个 Prompt 有角色、输入、输出、约束、证据要求与可替换占位符。 |
| `Agent开发学习记录表.xlsx` | 可长期维护的学习记录表：Dashboard、16 周计划、每日记录、技能矩阵、项目里程碑、评测、面试、错题、故障与官方资料。 |
| `example_project/` | 可执行的 Python 示例项目，包含 FastAPI、Pydantic、模型适配器、受限 Agent Loop、工具、SQLite 审计、Docker、pytest 与 JSONL 评测。 |
| `research/framework_notes.md` | 本学习包引用的官方资料与工程选择记录，便于更新版本。 |

## 推荐使用顺序

第一步，打开 `Agent开发学习记录表.xlsx` 的“学习总览 Dashboard”和“技能矩阵”，完成入学诊断并确定是否需要补齐 Python、HTTP、SQL、Git、pytest 或 Docker 基础。第二步，每周按主教程对应章节完成每日任务。每日都在“每日学习记录”中写入实际小时、状态、代码路径、测试/trace/报告等证据，而不是仅记录“学习了某知识”。

第三步，在第 7 周前完成 `example_project/` 并保持测试通过。示例项目的核心价值在于把模型建议与服务端控制分开：模型只能提出工具调用；服务端负责 Pydantic 校验、权限、租户、审批、幂等、超时和审计。第四步，在第 9–13 周建立自己的 RAG、评测和安全 JSONL 资产。第五步，使用 Week 14–16 的规格完成两个作品集，录制一个正常路径、一个拒绝路径、一个故障/恢复路径的演示。

## 示例项目启动与验证

示例的身份 headers 仅用于本机教学，不可作为生产认证方案。生产环境必须通过验证过的 JWT、OIDC session 或企业 IdP middleware 生成 principal，并在后端、数据库和检索层强制用户、角色与租户策略。

```bash
cd example_project
cp .env.example .env
python -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
pytest -q
mypy src
python eval/run_eval.py --input eval/cases.jsonl --output eval/report.json
uvicorn agent_app.main:app --reload
```

本学习包构建时已执行示例项目的 `pytest -q`（5 项通过）、`mypy src`（无问题）和 4 条离线 JSONL 评测（4 项通过）。这些只是教学样例验证，不代表模型供应商、真实企业文档、真实身份系统、真实网络或生产部署的测试已完成。

## 版本与安全说明

本学习包的技术资料基准日期为 **2026-08-12**。Agent SDK、LangGraph、Microsoft Agent Framework、MCP 和模型 API 变化较快，实际开始项目或升级依赖前，请复核对应官方 release notes、模型支持范围、弃用公告、迁移指南、价格和限额。不要把示例中的模型名、包版本或任何价格表当成永久事实。

所有用户输入、网页、PDF、RAG 片段、MCP 工具描述、工具输出和外部 API 响应都应视为不可信数据。它们不能覆写系统策略，不能决定 principal/tenant/role，不能绕过审批，也不能直接触发高风险写操作。对于真实生产系统，还需要补齐身份认证、密钥管理、数据库迁移、数据保留、DLP、速率限制、监控告警、备份、灰度和回滚。
